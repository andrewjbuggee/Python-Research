WHERE THE ERA5 DATA COMES FROM
   On Casper, ERA5 is read in place from GDEX: /gdex/data/d633000 (formerly RDA ds633.0).
   Nothing is downloaded, to Casper or to the laptop. Decoded chunks are cached in
   /glade/derecho/scratch/abuggee/era5_cache, so repeat passes are cheap. That cache is
   disposable and scratch is purged after 180 days of no access.

LOGIN NODES
   You can look at GDEX files from a login node, but do NOT run these scripts there. NCAR
   automatically terminates login-node processes using excessive CPU, excessive I/O or more
   than a few GB of memory:
   https://ncar-hpc-docs.readthedocs.io/en/latest/compute-systems/casper/casper-use-policies/
   Use a PBS job (step 3) or an OnDemand Jupyter session (step 4). The scripts print a warning
   if they find no PBS job.

3. SUBMIT JOBS (recommended for anything bigger than a small box)
   From ~/Python-Research/ERA5/surface_energy_budget/aws_pipeline/casper

   Preview, submits nothing:
       ./submit.sh --box 82 -175 65 -110 --region-name beaufort_wide --csvs all --dry-run

   CSV and netCDF products:
       ./submit.sh --box 82 -175 65 -110 --region-name beaufort_wide --years 2014-2024 --csvs all
       ./submit.sh --region arctic_circle --csvs hour_count,per_cell
       Products: hour_count  per_cell  precip  cumulative  ice_vs_water  hourly  netcdf
       Also, only when named: supercooled (see make_era5_supercooled_check.py)

   Figures:
       ./submit.sh --box 82 -175 65 -110 --region-name beaufort_wide --years 2014-2024 --all

   Start small. A one-season run is a cheap test of a new domain:
       ./submit.sh --box 82 -175 65 -110 --years 2023 --csvs hour_count

   Memory: --csvs jobs request 16 GB. Use --mem to change it, e.g. --mem 32GB. Each job's log
   prints its peak memory, and qhist shows approximate usage in the Mem column.

   Watch:   qstat -u $USER
   Cost:    qhist -u $USER -d 1

WAYS TO NAME A DOMAIN
   --box N W S E                   any box, degrees, longitudes -180..180
   --box 75 170 65 -170            W > E crosses the dateline (170 E to 170 W)
   --region arctic_circle          a name in ERA5/surface_energy_budget/era5_seb_variables.py
   OV_REGION=box:82,-175,65,-110   same thing from the environment or in the notebook
   To keep a domain under a name, add one line to REGIONS in era5_seb_variables.py.

   Priority: command line, then OV_* environment variables, then the settings at the top of
   ov_config.py.

YEARS
   Season START years: 2014 means 1 Oct 2014 - 31 Mar 2015.
   --years 2023    --years 2014-2024    --years 2014,2016-2018
   Each season stays 1 Oct - 31 Mar in these scripts.

CELL WEIGHTING
   Averages over a surface class (per_cell, precip, hourly) are area-weighted by cos(latitude)
   by default. --cell-weighting uniform gives per-grid-cell averages instead, and works on the
   scripts and on submit.sh. Area-weighted folders and files have "areaWeighted" in their names,
   so they never replace uniform ones. hour_count tables are plain counts either way.

SUPERCOOLED-ONLY FILTER (on by default on Casper)
   With GDEX (or S3), liquid-containing and liquid-only statistics keep only cell-hours
   whose cloud temperature is below 0 C. Cloud temperature = liquid-water-path-weighted
   mean temperature of the column from the 23 pressure levels (cloud_temp_filter.py).
   Cell-hours with no pressure-level liquid are dropped too; ice-only and clear-sky are
   untouched. Applies to hour_count, per_cell, precip, cumulative, ice_vs_water (lc_* rows),
   hourly and netcdf. NOT to supercooled (the diagnostic itself) or the figure notebook.
   Laptop runs from local files leave it off (pressure levels for 2024/25 only).
       --supercooled-only auto|on|off    on the scripts and on submit.sh
       OV_SUPERCOOLED_ONLY=off           same thing from the environment
   Filtered output goes to its own folder, <domain>_<span>_supercooled, so it never
   replaces unfiltered tables. Each log prints how many cell-hours the filter dropped,
   and the readME files record it. It re-reads pressure levels, so jobs take longer;
   the chunk cache makes every job after the first much cheaper.

DOMAINS WITHOUT UTQIAGVIK (71.323 N, 156.609 W)
   UTQ tables and ARM-cell figures (1, 2, 3, 4, 7a, 7c) are skipped, because the code would
   otherwise label the nearest edge cell as the ARM cell. Domain-wide output is still written.
   make_era5_utqiagvik_filtered_netcdf.py stops with a message, as it is only that cell.

ON THE LAPTOP
   Barrow still runs from the local files. Any other domain stops with an error rather than
   downloading anything. --storage s3 streams the AWS mirror of the same archive, but its chunk
   cache grows on the laptop's disk (ERA5_CACHE moves it).

IF SOMETHING GOES WRONG
   "Domain ... is not on this disk"   You are on the laptop with a new domain. Use Casper.
   "no project code"                  export PBS_ACCOUNT=UCSD0090, or pass --project UCSD0090.
   "no ~/.era5_casper_env"            Run ./setup_casper.sh (step 2).
   Session emailed as terminated      It ran on a login node. Use step 3 or 4.
   Job killed at walltime             The walltimes in submit.sh are estimates. Raise them
                                      (24 h maximum) or run fewer seasons per job. The chunk
                                      cache makes a rerun faster.
